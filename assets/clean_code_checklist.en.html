Minimal Clean Code Checklist

First-Principles Edition · tick items while auditing a skill script · the criteria are cost and risk, not checklist-compliance
Root premise: code is written for humans (machines only care whether syntax is valid, not naming / length / comments).
From this, only two criteria follow — A. Comprehension cost (is intent and boundary obvious at a glance) · B. Change risk (a change doesn't quietly break something else).
Every rule is a subtree of these two; anything that fails the test is just noise.

Criteria, not a checklist: fix red; amber is temporarily acceptable if "comment + scoped"; green means clean. Checklist-for-its-own-sake (split into seven tiny functions just to be short, abstract an unused interface just for DRY) is itself dirty.
