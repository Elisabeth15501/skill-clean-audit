# 代码气味交叉对照表（Smells Crosswalk）

把 Uncle Bob 那套经典「代码气味」重新接地到本 skill 的两轴判据（A. 理解成本 / B. 修改风险）。
目的不是再列一遍原则，而是给审计一个**标准命名**——你看到某处脏代码时，能叫出它的名字，并立刻知道它抬高的是 A 还是 B、对应哪档严重度。

> 哲学提醒：下表每一项仍是「抬高理解成本或修改风险」的具体表现，不是独立教条。判据永远是 A/B 两轴，气味只是它们的别名。

## 一、Uncle Bob 的四大设计臭味 → 两轴

| 气味（Uncle Bob 命名） | 抬高哪轴 | 我的严重度 | 第一性原理判定 | 审计取证要点 |
|---|---|---|---|---|
| **Rigidity（僵化）** | B | 🔴 红 | 小改动引发连锁改动 → 修改风险高 | 改一处要同步改 N 处；找「改 X 必须顺带改 Y/Z」的依赖 |
| **Fragility（脆弱）** | B | 🔴 红 | 改一处，不相关的代码崩了 → 修改风险高 | 改 A 模块却触发 B 模块报错；耦合未显式化 |
| **Immobility（不易移动）** | A + B | 🟡 黄 | 想复用却被迫拖入一堆依赖 → 理解+修改双高 | 复制模块时连带 import 整片无关代码 |
| **Needless Complexity（无谓复杂）** | A | 🔴 红（反模式） | 为「将来可能」过度抽象 → 理解成本飙升 | 没人调用的通用接口、提前的工厂/策略模式 |
| **Needless Repetition（无谓重复）** | B | 🔴 红 | 复制粘贴 → 改一处忘一处 | 同类逻辑 ≥ 3 处；见「轻量指标信号」 |
| **Opacity（晦涩）** | A | 🔴 红 | 读不懂 → 理解成本最高 | 命名天书、隐式魔法、注释退化成 changelog |

## 二、结构级气味 → 两轴

| 气味（Uncle Bob 命名） | 抬高哪轴 | 我的严重度 | 第一性原理判定 | 审计取证要点 |
|---|---|---|---|---|
| **Long Function（长函数）** | A | 🟡 黄（内聚难拆时） | 认知负荷超限 → 理解成本 | 行数 > 40；看是否仍做「一件事」 |
| **Large Class（大类）** | A + B | 🟡 黄 | 职责过多 → 理解+修改双高 | 单文件/单类管多件不相干的事 |
| **Long Parameter List（长参数）** | A | 🟡 黄 | 调用处难读懂意图 → 理解成本 | 参数 ≥ 4；优先抽 options 对象 |
| **Boolean Flags（布尔旗）** | A | 🟡 黄 | 函数实际做两件相反的事 → 违反单一职责 | `dry_run=False` / `is_test=True` 类参数 |
| **Switch/Case on Type（对类型 switch）** | B | 🔴 红 | 加一种类型就要改这里 → 修改风险 | `if kind == "a": ... elif kind == "b"` 散落多处 |

## 三、与本 skill 清单项的对应

| 本 skill 红项 | 等价的 Uncle Bob 气味 |
|---|---|
| 符号来源隐式 `import *` | Opacity |
| 重复/矛盾说明 | Opacity（注释失修） |
| 注释退化成 changelog | Opacity |
| 模块级可变全局控行为 | Fragility（状态被隐式改写） |
| 命名与行为不一致 / 隐藏副作用（CQS 违反） | Opacity + Fragility（名字骗人） |
| 重复逻辑 DRY 违反 | Needless Repetition |
| 裸 `except` 静默吞错 | Fragility（失败被藏，下次引爆未知） |

| 本 skill 黄项 | 等价的 Uncle Bob 气味 |
|---|---|
| 长函数 > 40 行 | Long Function |
| 魔法量未命名 | Opacity（需猜含义） |
| best-effort `except` | （Uncle Bob 也允许「顶层 try-catch」，但要求异常按调用方定义） |

> 用法：审计时先在脑子里给每个发现贴一个上表中的「气味名」，再标它属于 A 还是 B、红还是黄。这样报告读者（包括学过 Uncle Bob 的人）能立刻对接已有认知，同时不偏离第一性原理。
